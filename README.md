# 期数采集台

**Ubuntu 24.04 / Rocky Linux 9 部署**：已提供 `deploy/ubuntu-24.04.sh` 和 `deploy/rocky-9.sh`，支持当前 9.x 稳定维护版本、源码或运行包安装、更新备份与定时服务。[查看部署步骤](deploy/INSTALL-UBUNTU-ROCKY.md)。

当前版本新增独立账号、工作台自定义文件夹、来源与按期资料单条/批量删除、回收站，以及可配置的科技风总览。Sites 版本保留所有者外层访问限制，首次在系统设置创建主管理员，随后使用独立账号密码。没有生产默认用户名或默认密码。

Linux 使用 Node.js 24 + SQLite 的独立生产构建，`npm run build:linux` 输出 dist-linux。系统每分钟检查采集计划，可按北京时间执行每天 19:00、每 120 分钟或每天 21:40 开奖。完整部署、HTTPS、systemd、备份导入说明见 [deploy/README.md](deploy/README.md)。

“工作台 → 资料目录”可以创建 8 层内的文件夹、改名、移动和排序。新建/编辑采集来源时选择保存文件夹；目录与资料解析类型分别保存，移动 36 码栏目不会改写核验规则。删除目录及其下级只将栏目移至未分类，原文保留。来源删除会暂停，恢复也保持暂停。单条或跨页选择后批量删除资料，数据墓碑防止后续采集重新显示已删记录，系统设置内可恢复。删除马上从统计分母移除。

独立账号角色：管理员管理设置和用户，操作员管理资料，只读用户仅查看。服务器逐项校验角色；用户可改本人密码，管理员可重置其他用户密码、停用或调整角色；密码/角色/状态变更撤销原会话。随机会话只保存摘要；密码采用随机盐 PBKDF2-SHA256，按兼容 Workers 的 100000 次迭代，12–128 位，配合登录尝试限制和 HttpOnly/SameSite Cookie。网站上的密码与 ChatGPT 密码不同。原私有服务端点保留 Sites 访问边界；Linux 必须配置后台专用密钥。

迁移备份不包含有效会话或环境密钥。Linux 导入只接受新空数据库，不覆盖已有资料。测试包括 `tests/management.test.mjs` 和独立本地端口 5273 上的 `tests/management-workflow.mjs`；后者使用明确的本地测试账号，绝不是生产默认账号。

用于网页资料采集、原文留档、开奖核验与正确率统计的私人 Web 系统。正式系统从空资料库开始，没有文档导入，也没有预置作者或预测记录。

## 新建自动采集栏目

1. 点击「新增采集来源」，填写网站地址和栏目名称，例如「白小姐15码」。
2. 粘贴该栏目完整的一期样本。样本用于定位网页栏目，不直接写入采集记录。
3. 选择自动识别，预览系统从网站实际读取的对应栏目。确认年份、类型及识别完整性。
4. 新增栏目默认勾选「启用自动采集」和「保存成功后立即采集一次」。保存时先采集网站现有资料，以后按计划追加新期数并去重。可按需要取消勾选；编辑现有栏目保留其启用状态，立即采集不默认勾选。

未识别成功也能保留配置：系统保存网址、样本和计划，将栏目设为「待识别」并暂停自动采集。修改后可再次预览和保存，无需反复填写。

在「系统设置 → 自动采集时间」选择按间隔采集，或每天固定时间（例如 16:30，北京时间）。新栏目默认跟随全站计划，也可以单独指定时间。暂停栏目不会访问来源网站或重新采集。网页位置变化时系统记录原因，并保留已填写配置。

## 资料导航和独立页面

左侧使用「资料类型 → 作者或栏目」树形菜单，可展开或收起。点击某个栏目，进入 `/materials/来源ID` 独立页面；只展示该栏目的按期原文、开奖结果、系统核验和统计。栏目网址可以直接收藏。

「采集资料」入口是按类型分组的目录页，不把所有栏目的原文堆在同一张表。总览页也以资料目录作为入口。

## 原文和核验

按来源、年份、期数唯一存档。首次原文保留文字、换行和符号；原站修改时追加版本记录，系统继续使用首次预测核验。人工修正解析会明确标记并归入历史回测。网页快照在无脚本的隔离预览中展示，保留最近 5 版；外部样式与图片无法加载时可能与原网页有视觉差异。

包含类号码、尾数、生肖、头数、单双命中为正确；半头按「头数 + 单双」组合判断，例如杀半头【0头双3头单】只排除 0 头双数和 3 头单数，不排除整个 0 头或 3 头；「杀」类在开奖属性未落入排除集合时为正确。五行、季节、段、门使用明确年度映射，缺失映射时待复核。

正确率 = 正确期数 ÷（正确期数 + 错误期数）；错误率使用同一分母。待开奖、未同步开奖、号码粘连、重复号码、缺失内容及数量不符的待复核记录不进入分母。按年份和期数匹配，不使用资料页面自写的「准」「错」作为依据。

可筛选类型、年份、期数范围、核验状态、开奖前留档或历史回测，支持 CSV 导出。

核验在读取资料与统计时，自动关联全部同年份、同期数的历史开奖；新增采集资料、补齐历史开奖或更正开奖后立即生效，不受表格分页限制。「采集资料」独立栏目页、「资料批量管理」及「开奖管理」提供「复核开奖结果」按钮，重新计算全部匹配记录并记录复核报告。缺失开奖仍待开奖，缺少规则仍待复核，既有采集失败结论保留。复核不会修改首次采集原文或采集时间。实时开奖、JSON 同步、历史开奖及开奖更正成功入库后，主动执行对应年份和期数的自动复核并记录报告；复核直接读取数据库，不访问资料网站。旧记录缺少解析对照时，从该栏目已经留档的完整号码表补全并留审计，来源暂时无法访问不影响已有资料复核。

## 推荐内容版本与历史回溯

按同一来源、年份、期数比较有效推荐内容，号码作为集合比较，忽略顺序、分隔符、空格及“特开／开奖”的结果文字和“准／中”标注。杀段4段变成3段、五行／生肖／尾数变化、五个号码被替换等均属于改料；单纯从“？00准”补为“狗21准／中”不新增资料版本，也不标记改料。两版均明确提供的号码分组发生实际变化时也会记录。无法完整解析的新内容不会被擅自认定为改料。

首次原文、推荐值和首次采集时间始终保留，统计和组合计算继续使用首次资料。真正的推荐变更按发现顺序留存版本，记录前后推荐值、原文、发现时间、独立开奖核验及结果快照；重复采集不新增相同版本，改回旧值仍作为一次新的变更保留。已确认开奖后发现推荐变更的资料展示“历史回溯”入口；开奖前的变更展示“资料版本”，均可在详情比较首次结果与后续版本。“修改筛选”可筛选历史回溯或所有推荐变更。

开奖前后根据已确认的开奖数据与发现时间判断；只有日期但无法确定同日先后时标为未确认，不伪造实际修改时间。旧版保存的原文差异会进行语义整理：只补开奖结果的旧记录不计为改料，旧原始证据仍保留；旧版本重新核验会注明“按现有开奖回溯核验”。解析修正与号码对照维护记录单独保留，不计为网站改料版本。数据库升级使用0006迁移，现有备份包含新增元数据。

## 组合计算与组合结果推送

工作台「组合计算」点击「新增组合计算」后建立空白方案，由用户手工选择基础号码池和需要排除的已采集资料，不预选栏目或创建模板。基础可选全部49个号码、一个已采集的推荐号码栏目（15码、30码、36码等）或手工号码。每项条件可排除（差集）或保留（交集）；例如杀虎会先展开同年份虎生肖对应的全部号码，再从当前基础集合移除。基础为30码时，后续所有步骤均在这30个号码内筛选。30码资料使用通用号码类型，仍校验标题声明的30个不同号码。

支持生肖、尾数、头数、半头、五行、段、门、波色、合数、单双、季节和已配置的生肖属性。页面展示逐步命中的号码、本步移除和剩余号码、首次原文、所用对照及计算时间。结果是资料条件对应的候选集合，没有统计概率排序。采集资料表格和数据源管理的操作保持原有方式；在单个采集栏目资料页下方保留该栏目自己的完整号码对照；杀段、杀行和五行记录同时在每期原文下方直接展开本期分组，例如“3段：15、16、17、18、19、20、21”“金行：04、05、12、13、26、27、34、35、42、43”。列表、详情和识别预览使用记录自带的完整对照；缺少对照时明确提示，不按固定段数猜号码，原文和留档内容不变。

所有条件按同年份、同期数关联，可指定期数、选择所选资料最新一期（取最高期数，缺少该期资料的栏目等待补齐）、各栏目共同最新一期，或跟随可信开奖源明确公布的待开奖期数。缺少任何栏目、有效解析或完整对照时保留缺项记录，不生成可推送的最终集合；明确排除完49个号码时，零个候选是有效的计算结果。已删除资料及已记录采集失败的期数不参与完整计算。计算快照保留当时条件和原文，不因后续修改而改写；重复计算相同条件复用同一结果。

每套组合可以独立设置每天计算时间或分钟间隔（至少5分钟），并单独配置企业微信群推送时间。默认人工保存和试算，自动计算与自动推送均须勾选保存。默认勾选“计算前采集所选栏目最新资料”：手动试算、立即计算及定时计算先更新本组合选中的网络栏目，再确定期数并计算，额外采集不改变栏目原有下一次计划时间。可关闭此选项仅计算已留档资料。实时采集失败或最新一期缺项时阻止生成最终结果，五分钟后重试，不自动用旧期替代。仅自动计算和推送当天开奖前的完整结果，截止时间默认北京时间21:35，可自行调整。已开奖、跨日、条件已修改但尚未重算的结果不得作为新的开奖前结果推送；同组合同期只成功推送一次。

「企业微信推送」菜单提供已保存组合列表，可选择启用的组合并分别修改推送时间。组合推送复用已保存的机器人地址，与每日开奖结果推送的启用开关独立。操作员可以管理不带自动群推送的组合、试算与计算；管理员管理推送配置和发送。所有持久数据保存在现有settings表，随现有备份迁移，无需新增迁移。

来源页面明确打印的五行、生肖、段、门等49号码完整对照随资料采集，完整且无重叠的分类优先于年度公共对照；原表及不完整分组也留存供查看，不完整分类不自动混用公共表。属性分组允许明确的重叠。相同预测值的旧记录可以审计补全缺失对照，首次原文、推荐值和留档时间不变，开奖后补全归入历史核验。首次已保存的对照不会被冲突的新表覆盖。

旧记录首次原文里已经留存的对照表，会从该份原文直接提取并标注最初留档时间；即使原站后来删除了这期记录，也保留并使用自己的档案。

白小姐305期回归样本：正文位置变化时默认自动重新识别同一栏目：优先使用已确认的栏目标题和身份，再使用期数样本定位；原选择器消失、误指向其他作者、布局移动、训练期数被改写或嵌入正文地址变化时，可回到原网页重新寻找并保存新位置。名称重复或身份无法唯一确认时停止，不放宽到整页。高级设置可关闭自动重新识别，改用严格的手动位置。成功重新定位会记录运行日志。

测试：`tests/combination.test.mjs` 和 `tests/combination-workflow.mjs` 覆盖实际305期、栏目对照优先、条件交集/排除、零候选、缺项、首次原文保留、并发修改、结果去重、计算与推送分别计时、禁止混期/跨年/已开奖推送及账号权限。接口回归只使用隔离测试库和模拟机器人。

## 每日开奖推送配置

「工作台 → 企业微信推送」支持管理员保存群机器人 Webhook、设置每天推送时间（默认北京时间 21:40）、暂停推送、清除地址、发送连接测试和推送最新开奖。普通用户可查看消息预览和推送记录，Webhook 不在查询接口、日志或页面中返回；管理员迁移备份含此配置，应按含凭证的备份保管。

Linux 原有每分钟后台巡检在开奖同步后检查推送。仅发送当天完整的六个平码和一个特码，按原始顺序附带来源提供的生肖；不推算缺失生肖。开奖日期必须可确认，不把旧结果当成当天结果。到点未采齐时等待，失败五分钟后重试，成功的同年份同期数不再自动发送；数据库租约防止并发重复发送。连接超时与外部系统响应不确定时，网络层无法保证严格的恰好一次投递。清除 Webhook 自动暂停，未配置前不会发送消息。

接口仅接受企业微信官方 HTTPS 机器人地址，不允许任意回调或跳转。`tests/wecom-push.test.mjs` 覆盖日期、时间、完整结果及接口校验；`tests/recheck-push-workflow.mjs` 在隔离测试库与本地模拟发送端验证跨页复核、默认采集、权限、并发去重、重试和定时推送，不向真实企业微信群发送测试消息。

实时源未给出本期日期时，可使用该源之前明确公布并已留档的同年份、同期数开奖日期，不使用下一期日期或服务器当天日期填充。推送时间到了仍未收到当天完整结果时，每五分钟再同步一次已启用的开奖来源，收到后再推送；暂停开奖采集时不主动补采。

## 已接入的澳门开奖来源

用户指定 `https://mvqx1n.dlxyzw.com:1734/#dh` 网站头部「澳门彩」。系统通过其嵌入的开奖页发现实时推送地址，订阅澳门数据；只有七码完整且不同才保存特码和生肖，并保留推送原文。

## 定时任务

云端在每小时 30 分巡检到期来源。每天 16:30 的计划可对齐该巡检时刻，其他分钟会在之后一次巡检执行。页面分别展示设定时间与预计执行时间；实际启动可能受平台延迟影响，以日志为准。每个更新批次处理最多 8 个来源，并返回剩余数量，调度任务可以继续执行后续批次。开奖同步在同一轮中不会因分批重复连接。失败会显示原因并延后重试。

`POST /api/tick` 为后台更新入口。`POST /api/service` 提供配置开奖源、同步开奖、只读识别预览和读取运行状态四种维护操作。这两个入口使用所有者私有站点的平台访问校验，云任务通过站点服务访问凭证调用，凭证不写入代码或任务提示。

其他数据接口同时验证登录身份。网站保持所有者私人访问；如要开放多人或公共访问，需要先为后台入口和共享数据增加独立的权限设计。

## 支持范围

支持公开 HTML、文本正文、自定义栏目定位、常见 UTF-8 与 GBK 编码、受控跳转和超时错误记录。支持追踪同站点脚本中的静态 document.write / writeln 和 iframe 链，不执行来源脚本；最多追踪 8 个资源、3 层嵌套。识别后保存实际正文地址，后续直接采集正文。来源跳转到其他站点时会进行有限重试，仍不匹配则暂停，避免混入广告内容。HTML 定位使用 Cheerio；一个来源对应一个作者的一项资料。

已适配指定网站的动态开奖栏目。其他需要 JavaScript 渲染、登录、验证码或已失效的网站，需要实际资料页、正文接口或专门适配；系统会报告失败，不会把其他栏目误当作成功结果。

## 年度号码对照

工作台的「号码对照」菜单（`/?view=reference`）支持按年份管理十二生肖、五行、波色、合数单双及自定义生肖属性。管理员可填写网址，先采集预览再保存，也可通过表单手动维护。采集器跟进同站嵌入页和字面量 iframe 引用；对于已识别的年度对照模板，读取经过校验的数据数组并按所选年份计算，不执行来源网站的 JavaScript。静态页面或固定配置的年份与所选年份不一致时拒绝导入。

「49 号码明细」提供生肖、五行、波色、头数、尾数、合数、合数单双和生肖属性查询。头数、尾数与合数直接按号码计算；手动资料可分步补齐，缺失项保持为空，重复号码、越界和矛盾合数分组不能保存。支持同年份并发编辑冲突检测。

启用后，仅补充同年份资料核验所缺的属性，开奖源提供的生肖、五行优先。对照表保存在现有 `settings` 表，自动包含在迁移备份中，无需新增数据库迁移。只读用户和操作员可以查看，仅管理员可采集与修改。新资料类型支持波色、合数、合数单双和生肖属性。

验证：`node --test tests/number-reference.test.mjs tests/domain.test.mjs`。隔离的独立部署测试服务运行 `tests/management-workflow.mjs` 后，可执行 `tests/reference-workflow.mjs` 检查权限、并发、年份隔离、核验和备份。

## 动态正文与分段资料

支持 `shell.html?page=articles/…` 这类通过 CryptoJS/OpenSSL 格式加载正文的资料页。识别页面公开声明的同站接口和加载配置，读取正文后再定位栏目，不执行原站脚本。保存的正文位置保留栏目网址，后续定时采集仍可读取更新后的内容。

样本核对限定在同一期推荐内容，避免误匹配其他期数或页尾说明；“稳杀五码”等中文数量会检查是否为完整的五个号码。来源明确列出完整、互不重复的 1–7 段与 49 号码对照时，随当批资料保存该分段规则并用于核验。说明表单独保留在网页快照，不混入最后一期原文；未提供完整分段时保持待复核。

回归测试：`node --test tests/encrypted-shell.test.mjs`。隔离服务运行 `tests/management-workflow.mjs` 后，可执行 `tests/encrypted-source-workflow.mjs` 检查入库规则、重复采集和核验。接口测试可用 `QA_BASE_URL` 指定本机 5xxx 测试端口。

## 21:40 开奖与按期采集失败

开奖管理展示六个平码、特码和逐号生肖，按原始顺序保存，不推算缺失生肖。内置历史来源 https://2026kj.zkclhb.com:2026/am.html，可采集 2026 年全部开奖记录及站点已有的往年页面。按年份、期数去重，批量校验全部记录后写入；重复采集无重复记录，更正保留日志。历史页只提供日期时保存 draw_date，具体 drawn_at 仍为空。列表支持年份、期数筛选和分页，不再截断最近 100 期。

开奖计划固定每天北京时间 21:40，独立于资料采集计划；云端每日任务调用 POST /api/tick，由数据库计划控制是否到期，实时与历史同步分别报告错误。手动同步可随时执行。旧有每小时资料巡检的暂停状态不因新建每日开奖任务而自动改变。

每个资料来源可选择每天固定时间（如 19:00）或间隔分钟（120 即每 2 小时），并设置当期截止时间，默认 21:35。期数与日期只来自真实历史开奖记录或实时源明确提供的下一期日期，不把日历天数当期号。启用后开始跟踪，重新启用从当前时间起跟踪，暂停期间不补记失败。开奖截止后没有当期有效解析，持久化 collection_periods 失败结论；有旧期内容但无当期内容同样失败。以后补采原文仍保留失败判定。失败独立计数，不计入正确率、错误率分母。该结论可由云端任务或打开页面时完成，无需伪造空白预测原文。
